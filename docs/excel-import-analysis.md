# Анализ файла «Муж средний 2х2.xlsx» и схема импорта

## 1. Что внутри файла

Один лист (`Лист1`), 121 строка, 3 колонки, объединённых ячеек нет, формул нет.

| Колонка | Заголовок (строка 1)      | Пример значения |
|---------|---------------------------|-----------------|
| A       | `упражнения`              | `присед со штангой` |
| B       | `интенсивность`           | `легкая` / `средняя` / `тяжёлая` |
| C       | `подходы х повторения`    | `4х6-8` (кириллическая «х») |

Вертикальная структура — три уровня вложенности, размеченные **строками-маркерами**
(заполнена только колонка A):

```
блок 1                      ← мезоцикл / фаза (8 штук)
  тренировка 1              ← тренировочный день (голубая заливка #9FC5E8)
    присед со штангой | средняя | 4х6-8
    ...                       (6 упражнений)
  тренировка 2              ← тренировочный день (красная заливка #EA9999)
    жим лёжа | средняя | 4х8-12
    ...                       (6 упражнений)
блок 2
  ...
блок 8
```

Итого: **8 блоков × 2 тренировки × 6 упражнений = 96 строк упражнений**, 17 уникальных упражнений.

### Что меняется от блока к блоку
Набор упражнений почти постоянный (в блоке 3 присед → разгибания ног, французский жим →
разгибания в блоке, бицепс с супинацией → EZ-гриф; в блоке 5 жим лёжа → жим 30°,
вертикальная тяга → горизонтальная). Меняются **число подходов (3–6)** и **интенсивность**
— это волнообразная периодизация: в каждой тренировке часть упражнений «тяжёлые»
(5–6 подходов), часть «лёгкие/средние» (3–4 подхода), и в следующем блоке они меняются местами.

### Чего в файле нет
- рабочих весов и времени отдыха;
- комментариев (их роль выполняет колонка «интенсивность»);
- целевых мышц — их подставим из библиотеки упражнений по названию.

### Замеченные шероховатости (импорт должен их переживать)
| Где | Что | Как обработать |
|-----|-----|----------------|
| Блок 4, «жим лёжа» | `5х8-13` (вероятно опечатка 8-12) | Импортировать как есть, подсветить предупреждением в предпросмотре |
| Блок 4 | `тяжелая` без «ё» | Нормализация ё→е перед сравнением |
| Блок 8, «подъем на носки» | `средняя ` с пробелом | trim |
| Везде | разделитель `х` (кириллица) | Принимать `х`, `x`, `×`, `*` |
| Строка 2 | `блок 1` оформлен иначе, чем остальные блоки | Маркеры распознаём по тексту, а не по стилю |

## 2. Как интенсивность превращается в данные приложения

По инструкции автора программы интенсивность — это запас повторений, то есть прямо ложится на шкалу RIR:

| В таблице | Смысл у автора | Целевой RIR в приложении |
|-----------|----------------|--------------------------|
| лёгкая    | 5–7 повторений до отказа | 5–6 |
| средняя   | 3–4 до отказа | 3–4 |
| тяжёлая   | 1 до отказа или отказ | 0–1 |

Это важно для AdaptiveLoadEngine: правило «все подходы на верхней границе и RIR 3–6 →
увеличить вес» в лёгком блоке сработало бы ложно. Поэтому движок сравнивает фактический RIR
**с целевым RIR упражнения**, а если целевого нет — использует исходные правила из ТЗ.
При переходе упражнения между блоками разной интенсивности движок предлагает (но не применяет)
пересчёт веса через оценку 1ПМ с учётом RIR.

## 3. Во что превращается таблица

```
Program  "Муж средний 2х2"
├─ schedule: цикл [Тренировка 1, Тренировка 2, Отдых, Отдых]   (2х2, редактируемо)
├─ phases (блоки), по умолчанию каждый блок = 1 проход цикла (настраивается: N повторов)
│   ├─ Блок 1
│   │   ├─ Day "Тренировка 1"
│   │   │   ├─ ProgramExercise { exerciseId → «Присед со штангой» (библиотека),
│   │   │   │                    sets: 4, repsMin: 6, repsMax: 8,
│   │   │   │                    intensity: "medium", targetRir: [3,4],
│   │   │   │                    weight: null, restSec: 120 (по умолчанию для базовых), notes: "" }
│   │   │   └─ ...
│   │   └─ Day "Тренировка 2" ...
│   └─ ... Блок 8
```

- Каждое название сопоставляется с библиотекой упражнений (нормализация регистра, ё/е,
  пробелов + словарь синонимов). Не найденное — создаётся как пользовательское упражнение,
  в предпросмотре помечено «новое», группу мышц можно выбрать.
- Программа хранит «текущую позицию» (блок + день). Тренировка «Начать» берёт следующий
  день по позиции; календарь раскладывает расписание по датам.
- История тренировок хранит **снимок** предписания (подходы/повторения/RIR) и ссылку на
  `exerciseId`, а не на строку программы, поэтому правка или удаление программы историю не трогает.

## 4. Алгоритм импорта (обобщённый, не только под этот файл)

1. **Чтение**: SheetJS читает `.xlsx`, `.xls`, `.csv` в матрицу строк (все листы).
2. **Поиск заголовка**: первая строка, где ≥2 ячеек совпали со словарями колонок
   (`упражн|exercise|название`, `подход|sets`, `повтор|reps`, `подходы х повторения`,
   `вес|weight|кг`, `интенсив|rir|rpe`, `отдых|rest`, `коммент|заметк|notes`).
   Нет заголовка — эвристика по содержимому колонок (где текст, где `NхM`, где числа).
3. **Классификация строк**:
   - маркер блока — заполнена только 1 ячейка и текст `блок|неделя|фаза|мезоцикл|block|week|phase`;
   - маркер дня — `тренировка|день|day|workout|treniruvka N|A/B/C`, либо «День A — грудь…»;
   - строка упражнения — есть название и распознаётся хотя бы подходы/повторения;
   - пустые/прочие строки — пропускаются и попадают в отчёт.
   - Если листов несколько и маркеров дней нет — каждый лист считается днём.
4. **Разбор подходов/повторений**: `4х6-8`, `4x8–12`, `4 × 10`, `3x10,10,8`, `4х12+`,
   отдельные колонки «подходы» и «повторения».
5. **Вес**: `40`, `40 кг`, `40kg`, `@40`, `40-45`; **отдых**: `90`, `90с`, `1:30`, `2 мин`.
6. **Интенсивность**: лёгкая/средняя/тяжёлая, `RIR 2`, `RPE 8` (→ RIR 2).
7. **Отчёт**: список предупреждений (строка, ячейка, что не распознано) + предпросмотр,
   где всё редактируется до сохранения.
8. **Сохранение**: «Новая программа» или «Добавить в существующую» (если совпадает
   структура — добавляем блоки/дни, иначе показываем причину).
